```yaml
apiVersion: kafka.strimzi.io/v1beta1
kind: KafkaTopic
metadata:
  name: clicks
spec:
  kafka:
    bootstrapServiceName: my-cluster-kafka-bootstrap
    replicas: 3
    listeners:
      - name: plain
        port: 9092
        type: internal
      - name: tls
        port: 9093
        type: internal

      num.partitions: 6
```

### 3. Flink SQL `CREATE TABLE` statements

```sql
CREATE TABLE clicks (
  `session_id` STRING,
  `timestamp` TIMESTAMP,
  `event` MAP<STRING, STRING>
) WITH (
  'connector' = 'kafka',
  'topic' = 'clicks',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'properties.group.id' = 'my-group',
  'scan.startup.mode' = 'latest-offsets',
  'properties.deserialization-decoder' = 'json',
  'format' = 'json',
  'json.fail-on-missing-field' = 'true',
  'json.ignore-parse-errors' = 'true',
  'json.fail-on-missing-field' = 'true'
);

CREATE TABLE clicks_enriched (
  `session_id` STRING,
  `timestamp` TIMESTAMP,
  `event` MAP<STRING, STRING>,
  `derived_field1` STRING,
  `derived_field2` STRING
) WITH (
  'connector' = 'kafka',
  'topic' = 'clicks-enriched',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'properties.producer.transactional.id' = 'true',
  'format' = 'json',
  'properties.producer.acks' = 'all',
  'properties.producer.retries' = '3'
);

INSERT INTO clicks_enriched
SELECT
  `session_id`,
  `timestamp`,
  `event`,
  `derived_field1`,
  `derived_field2`
FROM clicks
WHERE `event` IS NOT NULL;
```

### Justification

The Kafka topic `clicks` and `clicks-enriched` are created with 6 partitions each, 3 replicas, and a retention period of 30 days. The `cleanup.policy` is set to `compact` to remove old data.

The Flink deployment is configured with 1 TaskManager pod, using 4 CPU and 8 GiB of memory each. The `taskmanager.numberOfTaskSlots` is set to 4, which means each TaskManager can run 4 subtasks in parallel. The `parallelism.default` and `parallelism.override` are set to 1 to ensure the job runs with 1 subtask.

The Flink configuration includes settings for exactly-once checkpointing, durable checkpoint storage, and producer settings. The `producer.acks` is set to `all` to ensure exactly-once delivery. The `producer.retries` is set to 3 to handle temporary failures.

The Flink SQL `CREATE TABLE` statements define the `clicks` and `clicks_enriched` tables, which are connected to the corresponding Kafka topics. The `clicks` table uses a JSON deserializer and fails on missing fields and parse errors. The `clicks_enriched` table uses a JSON serializer and producer with transactional ID for exactly-once delivery.
