### Justification

- **Kafka Topic Configuration:**
  - We create two Kafka topics, `ad-impressions` and `ad-impressions-enriched`, each with 16 partitions and 3 replicas. This configuration ensures that the topics can handle the input rate of 5,000 events/s and provide high availability.
  - We set the retention policy to compact, which removes the oldest log segment when the available space is low. We also set the segment.ms to 604800000 (7 days) to ensure that data is retained for at least 1 day.
  - We set the flush.ms to 10000 to ensure that data is flushed to disk regularly.
  - We set the min.insync.replicas to 2 and acks to all to ensure that data is written to at least two replicas before considering it written.
  - We set the max.in.flight.requests.per.connection to 5 to prevent overwhelming the brokers with too many requests.
  - We set the max.request.size to 1048576 to prevent large requests from overwhelming the brokers.
  - We set the message.max.bytes to 1048576 to prevent large messages from overwhelming the brokers.
  - We set the replication.factor to 3 to ensure that data is replicated to at least three brokers.

- **Flink Configuration:**
  - We create a Flink deployment with one TaskManager pod, which can use at most 4 CPU and 8 GiB of memory.
  - We set the taskmanager.numberOfTaskSlots to 4, which means each TaskManager can run up to 4 tasks concurrently.
  - We set the taskmanager.memory.process.size to 8g, which means each TaskManager can use up to 8 GiB of memory.
  - We set the parallelism.default to 4, which means each task will be executed in parallel with 4 tasks.
  - We set the state.backend to filesystem, which means Flink will store the state in the file system.
  - We set the state.checkpoints.dir to s3://flink-state/checkpoints, which means Flink will store the checkpoints in S3.
  - We set the state.checkpoints.interval to 10s, which means Flink will checkpoint every 10 seconds.
  - We set the state.checkpoints.num-retained to 24, which means Flink will retain 24 checkpoints.
  - We set the state.checkpoints.timeout to 1m, which means Flink will timeout after 1 minute if a checkpoint is not completed.
  - We set the restart-strategy to failover, which means Flink will restart the task if it fails.
  - We set the restart-strategy.failure-count to 3, which means Flink will restart the task after 3 failures.
  - We set the restart-strategy.delay to 10s, which means Flink will wait 10 seconds before restarting the task.
  - We set the restart-strategy.interval to 10s, which means Flink will restart the task every 10 seconds.
