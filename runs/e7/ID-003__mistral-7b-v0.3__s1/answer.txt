 1. Here's the `kafka-topics.sh` commands for creating the Kafka topics:

```bash
# Session events topic
kafka-topics.sh --create \
  --bootstrap-server kafka:9092 \
  --replication-factor 3 \
  --partitions 10 \
  --config retention.ms=604800000 \
  --config min.insync.replicas=2 \
  --config cleanup.policy=delete \
  --topic session-events

# Session events enriched topic
kafka-topics.sh --create \
  --bootstrap-server kafka:9092 \
  --replication-factor 3 \
  --partitions 10 \
  --config retention.ms=604800000 \
  --config min.insync.replicas=2 \
  --config cleanup.policy=delete \
  --topic session-events-enriched
```

Explanation:
- `--replication-factor 3` ensures the topics survive the loss of any single Kafka broker.
- `--partitions 10` allows for processing 10 partitions concurrently with Flink, matching the number of Flink TaskManagers.
- `--config retention.ms=604800000` sets the retention period to 7 days.
- `--config min.insync.replicas=2` ensures that a message is considered written only when at least 2 replicas have acknowledged it.

2. Flink configuration (`config.yaml` keys):

```yaml
job.type: Streaming
parallelism.default: 10
taskmanager.numberOfTaskSlots: 4
rest.port: 8081
checkpointing.mode: EXACTLY_ONCE
checkpointing.failure-tolerance-mode: EXACTLY_ONCE
checkpointing.timeout: 30000
checkpointing.min-pause: 3000
checkpointing.max-concurrent-checkpoints: 1
state.backend: filesystem
state.backend.fs.type: filesystem
state.backend.fs.checkpoint.dir: s3://flink-state/checkpoints
```

Explanation:
- `job.type: Streaming` sets the job type to a streaming job.
- `parallelism.default: 10` sets the parallelism for each Flink source and sink.
- `taskmanager.numberOfTaskSlots: 4` defines the number of slots available on each TaskManager.
- `rest.port: 8081` sets the Flink REST API listening port.
- `checkpointing.*` settings configure checkpointing for at-least-once delivery guarantee and to reduce the end-to-end latency.
- `state.backend: filesystem` sets the state backend to filesystem for durable checkpoints.
- `state.backend.fs.checkpoint.dir` specifies the location for checkpoints in S3.

3. Flink SQL `CREATE TABLE` statements:

```sql
CREATE TABLE session_events (
    user_id STRING,
    event_data JSON
) WITH (
    'connector' = 'kafka',
    'topic' = 'session-events',
    'properties.bootstrap.servers' = 'kafka:9092',
    'properties.group.id' = 'session-events-source',
    'format' = 'json',
    'json.ignore-parse-errors' = 'true'
);

CREATE TABLE session_events_enriched (
    user_id STRING,
    event_data JSON,
    derived_field1 INT,
    derived_field2 STRING
) WITH (
    'connector' = 'kafka',
    'topic' = 'session-events-enriched',
    'properties.bootstrap.servers' = 'kafka:9092',
    'properties.group.id' = 'session-events-enriched-sink'
);
```

Explanation:
- `session_events` creates the source table for reading from the `session-events` topic. The `'json.ignore-parse-errors'` property is set to 'true' to handle malformed events.
- `session_events_enriched` creates the sink table for writing to the `session-events-enriched` topic.
