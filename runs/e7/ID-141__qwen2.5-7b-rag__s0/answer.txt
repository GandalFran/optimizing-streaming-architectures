```bash
# Create Kafka topics with 3 partitions and 1 replica
kafka-topics.sh --create --topic app-logs --partitions 3 --replication-factor 1 --config retention.ms=86400000 --bootstrap-server kafka:9092
kafka-topics.sh --create --topic app-logs-parsed --partitions 3 --replication-factor 1 --config retention.ms=86400000 --bootstrap-server kafka:9092
```

```sql
-- config.yaml keys used: execution.checkpointing.interval, execution.checkpointing.mode, state.backend, state.checkpoints.dir, state.checkpoints.min-pause, state.checkpoints.num-retained, parallelism.default

CREATE TABLE app_logs (
  service STRING,
  event JSON
) WITH (
  'connector' = 'kafka',
  'topic' = 'app-logs',
  'properties.bootstrap.servers' = 'kafka:9092',
  'format' = 'json',
  'scan.startup.mode' = 'latest-offset',
  'sink.partitioner' = 'round-robin',
  'sink.delivery-guarantee' = 'exactly-once',
  'execution.checkpointing.interval' = '5s',
  'execution.checkpointing.mode' = 'EXACTLY_ONCE'
);

CREATE TABLE app_logs_parsed (
  service STRING,
  event JSON,
  derived_field1 STRING,
  derived_field2 STRING
) WITH (
  'connector' = 'kafka',
  'topic' = 'app-logs-parsed',
  'properties.bootstrap.servers' = 'kafka:9092',
  'format' = 'json',
  'sink.partitioner' = 'round-robin',
  'sink.delivery-guarantee' = 'exactly-once',
  'execution.checkpointing.interval' = '5s',
  'execution.checkpointing.mode' = 'EXACTLY_ONCE'
);
```

### Justification of Main Values

1. **Kafka Topics Creation**:
   - **Partitions and Replication Factor**: Set to 3 partitions and 1 replica to balance between throughput and fault tolerance. Given the input rate of 20,000 events/s, 3 partitions should be sufficient.
   - **Retention**: Set to 1 day (86,400,000 ms) to retain data for the required duration.

2. **Flink Configuration**:
   - **Checkpointing**: Enabled with an interval of 5 seconds and mode set to `EXACTLY_ONCE` to ensure exactly-once delivery guarantees.
   - **State Backend**: RocksDB is used for state storage.
   - **Parallelism**: Set to 3 to match the number of Kafka partitions.
   - **Externalized Checkpoints**: Stored in S3 to ensure durability.

3. **Flink SQL Tables**:
   - **Connector**: Kafka is used for both source and sink.
   - **Partitions**: `round-robin` partitioner is used to distribute the load evenly.
   - **Delivery Guarantee**: Set to `exactly-once` to ensure no duplicates and no loss.
   - **Scan Startup Mode**: Set to `latest-offset` to start consuming from the latest offset.
   - **Execution Checkpointing**: Interval and mode are set to ensure timely and reliable checkpoints.
