```sql
CREATE TABLE clicks (
    session_id STRING,
    event_data STRING,
    event_time TIMESTAMP(3) METADATA FROM 'timestamp'
) WITH (
    'connector' = 'kafka',
    'topic' = 'clicks',
    'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
    'format' = 'json',
    'scan.startup.mode' = 'latest-offset',
    'properties.group.id' = 'clicks-consumer-group'
);

CREATE TABLE clicks_enriched (
    session_id STRING,
    event_data STRING,
    enriched_field STRING,
    event_time TIMESTAMP(3)
) WITH (
    'connector' = 'kafka',
    'topic' = 'clicks-enriched',
    'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
    'format' = 'json',
    'sink.partitioner' = 'org.apache.flink.connector.kafka.sink.KeyPartitioner',
    'sink.partitioner-keys' = 'session_id',
    'sink.parallelism' = '25'
);
```

### Justification of Main Values

1. **Kafka Topic Partitions and Replicas**:
   - **Partitions**: 25 partitions are chosen to distribute the input rate of 50,000 events/s across the Kafka cluster, ensuring each partition handles up to 2,000 events/s (well below the assumed 5 MB/s limit). This also helps in achieving the desired end-to-end latency.
   - **Replicas**: 3 replicas ensure durability and availability, as the loss of any single broker will not result in data loss.

2. **Flink Configuration**:
   - **Parallelism**: 50 parallel subtasks are set to handle the input rate, with each subtask processing up to 1,000 events/s (since each TaskManager can handle up to 20,000 events/s and there are 3 TaskManagers).
   - **Checkpointing**: Configured for exactly-once semantics with a checkpoint interval of 5 seconds to ensure fault tolerance and low latency.
   - **State Backend**: RocksDB is used for state backend to ensure efficient state management and recovery.

3. **SQL Table Definitions**:
   - **Clicks Table**: Defines the source Kafka topic with JSON format and metadata extraction for timestamps.
   - **Clicks Enriched Table**: Defines the sink Kafka topic with a key partitioner to ensure data is written to the same partition based on `session_id`, which helps in maintaining order and reducing latency.
