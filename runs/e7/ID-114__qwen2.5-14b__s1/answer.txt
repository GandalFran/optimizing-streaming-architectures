### Justification of Values:
1. **Kafka Topic Partitions:**
   - **16 Partitions for `card-transactions` and `card-transactions-enriched`:** Given the input rate of 5,000 events/s and each event size of 2048 bytes, the total throughput is 10 MB/s. Since one partition can sustain up to 5 MB/s, 16 partitions are chosen to distribute the load evenly and achieve the desired throughput. Replication factor is set to 3 for redundancy and fault tolerance.

2. **Flink Configuration:**
   - **Parallelism:**
     - `parallelism.default: 2`: The job will run with 2 parallel instances, each having 2 task slots. This allows for a total of 4 task slots (2 * 2), ensuring the job can handle the throughput while staying within the resource constraints.
   - **Checkpointing:**
     - `execution.checkpointing.interval: "5s"`: Checkpoints every 5 seconds to ensure quick recovery and minimize data loss in case of failure.
     - `execution.checkpointing.mode: EXACTLY_ONCE`: Ensures exactly-once processing semantics, which is critical for the delivery guarantee.
   - **Task Manager Resources:**
     - `taskmanager.numberOfTaskSlots: 2`: Each task manager runs 2 slots, allowing for efficient resource utilization and scaling of the job.
   - **S3 Configuration:**
     - Provided necessary S3 configurations for checkpoint storage, ensuring durability and availability.

3. **Flink SQL Table Definitions:**
   - **Input Table (`card_transactions`):**
     - Defined with a JSON format and configured to start from the latest offset to ensure no data is missed.
   - **Output Table (`card_transactions_enriched`):**
     - Uses a JSON format and configured with a round-robin partitioner to ensure balanced writes to Kafka topic partitions.
