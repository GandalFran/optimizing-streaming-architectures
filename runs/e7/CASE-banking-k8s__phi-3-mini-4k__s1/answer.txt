```sql
CREATE TABLE banking_transactions (
  account_id VARCHAR,
  amount DOUBLE,
  transaction_type STRING,
  transaction_date TIMESTAMP,
  -- other relevant columns
) WITH (
  'connector' = 'kafka',
  'topic' = 'banking-transactions',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'properties.group.id' = 'banking_transactions_group',
  'scan.startup.mode' = 'earliest-offset',
  'format.schema.regex' = '$.account_id,$.amount,$.transaction_type,$.transaction_date'
);

CREATE TABLE banking_transactions_validated (
  account_id VARCHAR,

  transaction_type STRING,

  -- other relevant columns
) WITH (
  'connector' = 'kafka',
  'topic' = 'banking-transactions-validated',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'properties.group.id' = 'banking_transactions_validated_group',
  'scan.startup.mode' = 'earliest-offset',
  'format.schema.regex' = '$.account_id,$.amount,$.transaction_type,$.transaction_date'
);
```

The main values in the Kafka topics configuration are based on the given requirements. The number of partitions is set to 10, which allows for sustained input rate of 50,000 events per second with an average event size of 1024 bytes. The retention policy is set to 604800 seconds (7 days) to meet the retention requirement.

The Flink deployment configuration ensures that only one task manager pod can process at most 20,000 events per second. The Flink SQL job is packaged as a local JAR and deployed using Kubernetes Operator for Flink. The `spec.flinkConfiguration` includes the necessary settings for Flink to use the Kafka topic as a data source and sink.

The Flink SQL statements create two tables, one for the input Kafka topic and one for the output Kafka topic. The `format.schema.regex` property is used to parse the JSON input events. The `scan.startup.mode` property is set to `earliest-offset` to ensure that the Flink job starts processing the earliest available offset and maintains exactly-once semantics.
