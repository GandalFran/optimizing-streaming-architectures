CREATE TABLE banking_transactions (

### Justification of Values:

1. **Kafka Topics Configuration:**
   - `partitions: 4`, `replicas: 3`: Sufficient partitions and replicas to handle the input rate of 50,000 events/s. This ensures high availability and durability.
   - `retention.ms: 604800000`: Retention set to 7 days to keep data for the required duration.

2. **Flink Configuration:**
   - `taskManager.resources`: Set CPU and memory limits to ensure the TaskManagers can handle the workload.
   - `checkpointing.min-pause-between-checkpoints`: Ensures checkpoints are taken frequently enough to recover quickly in case of failures.
   - `state.backend.rocksdb`: RocksDB is chosen as the state backend for its performance and reliability.
   - `checkpointing.interval`: Set to 60 seconds to balance between recovery time and checkpoint overhead.
   - `network.rpc.bind-host: 0.0.0.0`: Allows the Flink JobManager to be accessible from outside the cluster.
   - `connectors.kafka.properties`: Configures the Kafka connector with exactly-once guarantees, setting the `isolation.level` to `read_committed` to ensure consistency.
   - `sources.kafka.properties` and `sinks.kafka.properties`: Configure the Kafka sources and sinks with the required properties for the transactional writes and reads.

3. **Flink SQL Table Statements:**
   - `WITH` clause includes necessary properties for Kafka connector, format, and isolation level to ensure exactly-once semantics and high availability.
