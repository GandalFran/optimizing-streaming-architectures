 1. Strimzi `KafkaTopic` resources for all topics:

```yaml
apiVersion: kafka.strimzi.io/v1beta2
kind: Kafka
metadata:
  name: my-cluster
spec:
  kafka:
    replicas: 3
    listeners:
    - name: plain
      port: 9092
      tls: false
      advertising: true
      openCluster: true
    entityOperator:
      replicas: 3
    zookeeper:
      replicas: 3
      storageClass: standard
    kafkaStorage:
      volumeClaimTemplate:
        storageClassName: standard
        resources:
          requests:
            storage: 10Gi

---
apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaTopic
metadata:
  name: banking-transactions
spec:
  replicas: 3
  partitions: 12
  config:
    retention.ms: 604800000
    cleanup.policy: delete
    segment.bytes: 1073741824
    compression.type: lzo

---
apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaTopic
metadata:
  name: banking-transactions-validated
spec:
  replicas: 3
  partitions: 12
  config:
    retention.ms: 604800000
    cleanup.policy: delete
    segment.bytes: 1073741824
    compression.type: lzo
```

In this configuration, we create a Kafka cluster with 3 brokers, and two topics, `banking-transactions` and `banking-transactions-validated`, with 12 partitions each. The partition size is set to 1 GB, allowing for a sustained input rate of 5 MB/s per partition. The retention period is set to 7 days (604800000 ms). Compression is enabled to reduce storage costs and improve throughput.

kind: Kustomization

resources:
- deployment.yaml
- service.yaml

patchesStrategicMerge:
- patch.yaml

---

apiVersion: apps/v1
kind: Deployment

  name: flink-sql-job
spec:
  replicas: 3
  selector:
    matchLabels:
      app: flink-sql-job
  template:
    metadata:
      labels:
        app: flink-sql-job
    spec:
      containers:
      - name: flink
        image: apache/flink:1.13.3
        imagePullPolicy: IfNotPresent

In this configuration, we create a Flink deployment with 3 replicas, each TaskManager pod can use at most 4 CPU and 8 GiB of memory, and at most 3 TaskManager pods may run. The Flink job is packaged as `local:///opt/flink/usrlib/sql-runner.jar`. Durable checkpoint storage is available at `s3://flink-state/checkpoints`.
