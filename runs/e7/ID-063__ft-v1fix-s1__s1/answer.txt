# 1. `kafka-topics.sh` commands to create all topics
```bash
# create topic 'sensor-readings'
./bin/kafka-topics.sh --create --topic sensor-readings --partitions 4 --replication-factor 3 --config retention.ms=604800000 --config cleanup.policy=compact --bootstrap-server kafka:9092

# create topic 'sensor-readings-clean'
./bin/kafka-topics.sh --create --topic sensor-readings-clean --partitions 4 --replication-factor 3 --config retention.ms=604800000 --config cleanup.policy=compact --bootstrap-server kafka:9092
```
# 2. Flink configuration (`config.yaml` keys)
```yaml
# the number of TaskManager slots available per TaskManager
jobmanager.numberOfTaskManagers: 3

# the number of operator parallelism
parallelism.default: 4

# the maximum parallelism of each Flink source subtask
source.parallelism: 20000

# the maximum parallelism of each Flink sink subtask
sink.parallelism: 20000

# checkpointing configuration
state.checkpoints.dir: s3://flink-state/checkpoints
state.checkpoints.type: snapshot
state.checkpoints.num-retained: 3
state.checkpoints.min-pause-between-checkpoints.ms: 1000
state.checkpoints.max-pause-between-checkpoints.ms: 60000
state.checkpoints.savepoint-dir: s3://flink-state/checkpoints

# job settings
job.name: SensorReadings
job.result-partitioning.num-partitions: 4
job.state-backend.type: filesystem
job.state-backend.fs.checkpoint-dir: s3://flink-state/checkpoints
job.state-backend.fs.dir: s3://flink-state/state
job.state-backend.fs.savepoint-dir: s3://flink-state/checkpoints

# network configuration
network.host: 0.0.0.0
network.port-range: 50000-59999
network.rpc-port: 6123
network.rpc-threads: 4
network.rpc-timeout: 30000
network.io-threads: 10

# taskmanager configuration
taskmanager.memory.process.size: 8GB
taskmanager.memory.fraction: 0.8
taskmanager.memory.network.max: 2GB
taskmanager.memory.heap.size: 4GB
taskmanager.memory.heap.size.min: 2GB
taskmanager.memory.off-heap.size: 2GB
taskmanager.memory.off-heap.size.min: 2GB
```
# 3. Flink SQL `CREATE TABLE` statements
```sql
# sensor readings source table
CREATE TABLE sensor_readings (
  sensor_id STRING,
  data JSON
) WITH (
  'connector' = 'kafka',
  'topic' = 'sensor-readings',
  'properties.bootstrap.servers' = 'kafka:9092',
  'format' = 'json',
  'scan.startup.mode' = 'latest-offset',
  'format.derived-columns' = 'clean_data = data->>\'clean_data\''
)

# sensor readings sink table
CREATE TABLE sensor_readings_clean (
  sensor_id STRING,
  data JSON
) WITH (
  'connector' = 'kafka',
  'topic' = 'sensor-readings-clean',
  'properties.bootstrap.servers' = 'kafka:9092',
  'format' = 'json',
  'sink.partition/table' = 'sensor_readings'
)
```
The main values in the configuration are:

- `jobmanager.numberOfTaskManagers: 3` and `taskmanager.memory.process.size: 8GB`: to handle 50k events/s with 512 bytes/event.

- `source.parallelism: 20000` and `sink.parallelism: 20000`: to handle 50k events/s with 512 bytes/event.

- `state.checkpoints.num-retained: 3` and `state.checkpoints.min-pause-between-checkpoints.ms: 1000`: to meet the end-to-end latency of 100ms at p99.

- `job.state-backend.type: filesystem` and `job.state-backend.fs.checkpoint-dir: s3://flink-state/checkpoints`: to achieve exactly-once end-to-end.

- `job.result-partitioning.num-partitions: 4`: to spread the load of the job evenly among the partitions.

- `network.io-threads: 10`: to handle the network traffic generated by the job.

- `network.rpc-timeout: 30000`: to handle any possible network delays.

- `taskmanager.memory.process.size: 8GB` and `taskmanager.memory.heap.size: 4GB`: to handle the large amount of state stored by the job.

- `sink.partition/table: sensor_readings`: to ensure that the sink table is partitioned according to the source table.
