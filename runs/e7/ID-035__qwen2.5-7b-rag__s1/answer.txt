```bash
# Create Kafka topics
kafka-topics.sh --create --topic session-events --partitions 3 --replication-factor 3 --config retention.ms=86400000 --bootstrap-server kafka:9092
kafka-topics.sh --create --topic session-events-enriched --partitions 3 --replication-factor 3 --config retention.ms=86400000 --bootstrap-server kafka:9092
```

### Justification of Main Values

1. **Kafka Topics Creation:**
   - **Partitions and Replication Factor:** Each topic has 3 partitions and a replication factor of 3 to ensure high availability and fault tolerance, while also meeting the durability requirement.
   - **Retention:** Both topics are set to retain data for 1 day (86,400,000 ms) to ensure data is available for as long as needed.

2. **Flink Configuration:**
   - **Heap Memory:** Configured with 8 GB for JobManager and 7 GB for each TaskManager to handle the processing load.
   - **Parallelism:** Set to 3, which matches the number of partitions for the Kafka topics to ensure balanced load distribution.
   - **Checkpointing:** Enabled with RocksDB as the backend and configured to retain 3 checkpoints, ensuring recovery in case of failures.
   - **Metrics Reporter:** Configured to send metrics to Kafka for monitoring and logging purposes.

3. **Flink SQL Tables:**
   - **Input Table (session_events):** Reads from `session-events` topic, configured to skip malformed records and use JSON format.
   - **Output Table (session_events_enriched):** Writes to `session-events-enriched` topic with at-least-once delivery guarantee, configured with a fixed partitioner to match the input topic's partitioning strategy, and buffer settings optimized for performance and durability.
