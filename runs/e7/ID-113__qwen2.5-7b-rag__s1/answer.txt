### Justification of Main Values:

1. **Kafka Topic Creation:**
   - **Partitions and Replication Factor:** We create 8 partitions for both `clicks` and `clicks-enriched` topics with a replication factor of 3 to ensure high availability and fault tolerance.
   - **Retention Period:** We set the retention period to 30 days (2592000000 milliseconds) for both topics to retain data for 30 days.

2. **Flink Configuration:**
   - **Parallelism:** We set the parallelism to 8 for both source and sink to match the number of Kafka partitions, ensuring that the data is evenly distributed.
   - **Checkpointing:** We enable checkpointing with `exactly-once` delivery guarantee, which ensures no duplicates and no loss of data.
   - **Checkpointing Interval:** We set the checkpointing interval to 5 seconds to balance between latency and durability.
   - **Partitioner:** We use the `fixed` partitioner to ensure that data is written to the same Kafka partition, maintaining consistency.

3. **Flink SQL Table Creation:**
   - **Table Schemas:** We define the schemas for the `clicks` and `clicks_enriched` tables, ensuring that the primary key constraint is enforced.
   - **Connector Configuration:** We configure the Kafka connector with `exactly-once` delivery guarantee and set the partitioner to `fixed` to ensure data is written to the correct Kafka partition.
   - **Sink Parallelism:** We set the sink parallelism to 8 to match the number of partitions and ensure efficient processing.
