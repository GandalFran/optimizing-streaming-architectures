 1. Strimzi `KafkaTopic` resources for all topics:

```yaml
apiVersion: kafka.strimzi.io/v1beta2
kind: Kafka
metadata:
  name: my-cluster
spec:
  kafka:
    replicas: 3
    listeners:
    - name: plain
      port: 9092
      tls: false
    inter broker:
      tls: false
    config:
      schema.registry.url: http://my-schema-registry:8081

---

apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaTopic
metadata:
  name: ad-impressions
spec:
  topic: ad-impressions
  partitions: 10
  replicas: 3
  config:
    retention.ms: 86400000
    max.message.bytes: 5242880
    min.insync.replicas: 2
    cleanup.policy: delete
    compression.type: lzo
    segment.bytes: 10485760

---

apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaTopic
metadata:
  name: ad-impressions-enriched
spec:
  topic: ad-impressions-enriched
  partitions: 10
  replicas: 3
  config:
    retention.ms: 86400000
    max.message.bytes: 5242880
    min.insync.replicas: 2
    cleanup.policy: delete
    compression.type: lzo
    segment.bytes: 10485760
```

Justification:
- `my-cluster` configures the Kafka cluster with 3 brokers and listeners.
- `ad-impressions` and `ad-impressions-enriched` are the topics for input and output, respectively. They have 10 partitions, which can handle the expected input rate (5,000 events/s sustained). The retention and max.message.bytes are set according to the requirements.

2. `FlinkDeployment` resource:

```yaml
apiVersion: flink. Operator.k8s.io/v1alpha2
kind: FlinkDeployment
metadata:
  name: ad-impressions-sql-job
spec:
  kubernetesNamespace: my-namespace
  taskmanager:
    cpu: 4
    memory: 8Gi
    replicas: 3
  jobManager:
    cpu: 4
    memory: 8Gi
  config:
    taskmanager.numberOfTaskSlots: 1
    jobmanager.rpc.timeout: 10000
    jobmanager.rpc.address: jobmanager-rpc
    parallelism.default: 3
    parallelism.checkpointing.side-output: 1
    checkpointing.checkpointing-mode: EXACTLY_ONCE
    checkpointing.minPauseBetweenCheckpoints: 5000
    checkpointing.maxConcurrentCheckpoints: 3
    checkpointing.failure-tolerance.max-concurrent-checkpoints: 3
    state.backend: ROCKSDB_S3_STATEBACKEND
    state.backend.s3.access-key: <access-key>
    state.backend.s3.secret-key: <secret-key>
    state.backend.s3.bucket: s3://flink-state/checkpoints
    state.backend.rocksdb.db-dir: /flink/rocksdb
    rest.port: 8081
    jobmanager.remote.web-ui-port: 8082
  image: flink:1.13.0-scala_2.13
  jar: local:///opt/flink/usrlib/sql-runner.jar
  env:
  - name: FLINK_PARALLELISM
    value: "3"
  containerPorts:
  - name: flink-rest
    containerPort: 8081
    protocol: TCP
  - name: flink-web-ui
    containerPort: 8082
    protocol: TCP
  volumeMounts:
  - name: checkpoint-volume
    mountPath: /flink/checkpoints
  volumes:
  - name: checkpoint-volume
    persistentVolumeClaim:
      claimName: flink-checkpoints
```

Justification:
- The FlinkDeployment specifies the desired resources for the JobManager and TaskManagers, the number of TaskSlots, checkpointing settings, and the S3-based state backend. The image and jar are specified, and the parallelism is set to 3 (to match the number of TaskManagers).

3. Flink SQL `CREATE TABLE` statements:

```sql
CREATE TABLE ad_impressions (
    campaign_id VARCHAR,
    event_data STRUCT<
        timestamp BIGINT,
        ad_id VARCHAR,
        impression_id VARCHAR
    >
) WITH (
    'connector' = 'kafka',
    'topic' = 'ad-impressions',
    'format' = 'json',
    'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
    'properties.group.id' = 'ad-impressions-sql-job',
    'json.ignore-parse-errors' = 'true'
);

CREATE TABLE ad_impressions_enriched (
    campaign_id VARCHAR,
    event_data STRUCT<
        timestamp BIGINT,
        ad_id VARCHAR,
        impression_id VARCHAR,
        derived_field1 VARCHAR,
        derived_field2 VARCHAR
    >
) WITH (
    'connector' = 'kafka',
    'topic' = 'ad-impressions-enriched',
    'format' = 'json',
    'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
    'properties.key.serializer' = 'org.apache.kafka.common.serialization.StringSerializer',
    'properties.value.serializer' = 'io.confluent.kafka.serializers.KafkaAvroSerializer',
    'properties.value.schema' = '<schema for the enriched event>'
);
```

Justification:
- The first `CREATE TABLE` statement sets up the Kafka source for the ad impression events, with the appropriate serialization properties and the option to ignore parse errors.
- The second `CREATE TABLE` statement sets up the Kafka sink for the enriched ad impression events, with the appropriate serialization properties and a schema for the enriched event. The schema will need to be defined according to the derived fields in your application.
