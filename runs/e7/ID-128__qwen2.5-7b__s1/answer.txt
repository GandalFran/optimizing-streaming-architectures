```sql
CREATE TABLE clicks (
  session_id STRING,
  event_time TIMESTAMP(3),
  event_data STRING,
  PRIMARY KEY (session_id) NOT ENFORCED
) WITH (
  'connector' = 'kafka',
  'topic' = 'clicks',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format' = 'json',
  'scan.startup.mode' = 'latest-offset',
  'value.format' = 'json'
);

CREATE TABLE clicks_enriched (
  session_id STRING,
  event_time TIMESTAMP(3),
  event_data STRING,
  derived_field STRING,
  PRIMARY KEY (session_id) NOT ENFORCED
) WITH (
  'connector' = 'kafka',
  'topic' = 'clicks-enriched',
  'properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format' = 'json',
  'sink.partitioner' = 'round-robin',
  'sink.flush.max-records' = '10000',
  'sink.flush.interval' = '10s'
);
```

### Justification of Main Values:
1. **Kafka Topic Configuration:**
   - **Partitions (16):** Each topic has 16 partitions to handle the high input rate (20,000 events/s) and ensure parallelism.
   - **Replicas (3):** Three replicas ensure high availability and fault tolerance.
   - **Retention (7 days):** Retention is set to 7 days to store historical data while keeping the cluster size manageable.
   - **Segment Bytes (104.85 MB):** This value is set to ensure that each segment file does not grow too large, which helps in efficient management of log segments.

2. **Flink Configuration:**
   - **Parallelism (16):** Set to match the number of partitions for parallel processing.
   - **State Backend (Filesystem):** Utilizes S3 for checkpointing to ensure durability.
   - **Checkpoint Interval (60 seconds):** Ensures that checkpoints are created frequently enough to meet the latency requirements.
   - **TaskManager Resources (4 CPU, 8GiB):** Configured based on the assumed maximum processing rate of 20,000 events/s per TaskManager.
   - **Checkpointing and Savepoints:** Configured to retain multiple checkpoints and savepoints for fault tolerance and recovery.

3. **Flink SQL Tables:**
   - **Clicks Table:** Configured to read from the `clicks` topic, using JSON format and enforcing a primary key on `session_id`.
   - **Clicks Enriched Table:** Configured to write to the `clicks-enriched` topic, using JSON format and enforcing a primary key on `session_id`. The `sink.flush` properties ensure that data is flushed periodically to maintain the latency requirement.
