```bash
# Create the Kafka topics
kafka-topics.sh --create --topic session-events --partitions 3 --replication-factor 3 --config cleanup.policy=compact --bootstrap-server kafka:9092
kafka-topics.sh --create --topic session-events-enriched --partitions 3 --replication-factor 3 --config cleanup.policy=compact --bootstrap-server kafka:9092
```

```sql
-- Flink SQL CREATE TABLE statements

-- Define the Kafka source table for session events
CREATE TABLE session_events (
    user_id STRING,
    event_json STRING,
    event_time TIMESTAMP(3) METADATA FROM 'timestamp'
) WITH (
    'connector' = 'kafka',
    'topic' = 'session-events',
    'properties.bootstrap.servers' = 'kafka:9092',
    'format' = 'json',
    'scan.startup.mode' = 'latest-offset',
    'sink.partitioner' = 'round-robin'
);

-- Define the Kafka sink table for enriched session events
CREATE TABLE session_events_enriched (
    user_id STRING,
    event_json STRING,
    event_time TIMESTAMP(3),
    derived_field1 INT,
    derived_field2 STRING
) WITH (
    'connector' = 'kafka',
    'topic' = 'session-events-enriched',
    'properties.bootstrap.servers' = 'kafka:9092',
    'format' = 'json',
    'sink.partitioner' = 'round-robin',
    'sink.checkpoint.min-records-per-batch' = '1000'
);
```

### Justification of Main Values:
1. **Kafka Topic Configuration:**
   - **Partitions (3):** To handle the input rate of 5,000 events/s, 3 partitions are used to distribute the load across multiple Kafka brokers.
   - **Replication Factor (3):** Ensures high availability and durability of data, as data is replicated across all brokers.
   - **Cleanup Policy (compact):** This policy keeps only the latest version of each key and removes older versions, which helps in managing data retention and compaction.

2. **Flink Configuration:**
   - **Parallelism (3):** Set to match the number of Kafka partitions to ensure balanced load.
   - **Checkpointing:** Configured for END_OF_EVENT_TIME with a 1-minute interval to ensure timely recovery and fault tolerance.
   - **State Backend (rocksdb):** Provides reliable state storage with efficient checkpointing.
   - **Durable Checkpoints:** Stored in S3 to ensure data persistence and availability across failures.

3. **Flink SQL Tables:**
   - **Source Table (session_events):** Defined to consume events from the `session-events` topic, with metadata for timestamp extraction.
   - **Sink Table (session_events_enriched):** Configured to write enriched events to the `session-events-enriched` topic, ensuring data is written in a round-robin fashion to distribute load across partitions. The `sink.checkpoint.min-records-per-batch` is set to ensure efficient batch processing and checkpointing.
