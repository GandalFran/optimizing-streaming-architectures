```bash
# Create the `app-logs` topic with 10 partitions and replication factor 3
kafka-topics.sh --create --topic app-logs --bootstrap-server kafka:9092 --replication-factor 3 --partitions 10 --config retention.ms=86400000

# Create the `app-logs-parsed` topic with 10 partitions and replication factor 3
kafka-topics.sh --create --topic app-logs-parsed --bootstrap-server kafka:9092 --replication-factor 3 --partitions 10 --config retention.ms=86400000
```

```yaml
# Flink configuration
config:
  state.backend: rocksdb
  state.checkpoints.dir: s3://flink-state/checkpoints
  state.checkpoints.num-retained: 10
  execution.checkpointing.mode: EXACTLY_ONCE
  execution.checkpointing.interval: 60000
  execution.checkpointing.timeout: 600000
  execution.checkpointing.min-pause: 5000
  parallelism.default: 10
  taskmanager.numberOfTaskSlots: 4
  jobmanager.execution.failover-strategy: region
```

```sql
-- Define the source table for the `app-logs` topic
CREATE TABLE app_logs (
    service STRING,
    log_event JSONB,
    event_time TIMESTAMP(3) METADATA FROM 'timestamp' VIRTUAL
) WITH (
    'connector' = 'kafka',
    'topic' = 'app-logs',
    'properties.bootstrap.servers' = 'kafka:9092',
    'properties.group.id' = 'app-logs-group',
    'format' = 'json',
    'scan.startup.mode' = 'latest-offset',
    'json.timestamp-format.standard' = 'ISO-8601'
);

-- Define the sink table for the `app-logs-parsed` topic
CREATE TABLE app_logs_parsed (
    service STRING,
    log_event JSONB,
    event_time TIMESTAMP(3)
) WITH (
    'connector' = 'kafka',
    'topic' = 'app-logs-parsed',
    'properties.bootstrap.servers' = 'kafka:9092',
    'format' = 'json',
    'sink.partitioner' = 'round-robin'
);
```

**Justification of main values:**

- **Kafka Topic Partitions:** The `app-logs` and `app-logs-parsed` topics each have 10 partitions to handle the input rate of 20,000 events/s (20,000 events/s per partition). This ensures that the Kafka brokers can handle the throughput without bottlenecks.
- **Flink Parallelism:** The default parallelism is set to 10 to match the number of partitions in the Kafka topics, ensuring that each Flink subtask processes events from a single Kafka partition, which helps in maintaining the order of events within each partition.
- **Checkpointing:** Checkpointing is configured for exactly-once semantics with a 1-minute interval to ensure fault tolerance and end-to-end exactly-once delivery. The checkpoint timeout is set to 10 minutes to allow for longer processing times if needed.
- **TaskManager Slots:** Each TaskManager has 4 slots, allowing for 12 slots in total across the cluster, which is more than the required 10 slots for the parallelism.
- **Retention:** Both Kafka topics retain data for 1 day, as specified in the requirements.
- **End-to-End Latency:** The configuration aims to keep the end-to-end latency below 10 seconds at p99 by optimizing the parallelism and checkpointing intervals.
