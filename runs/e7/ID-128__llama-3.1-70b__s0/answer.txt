```sql
-- Flink SQL CREATE TABLE statements for Kafka source and sink tables
CREATE TABLE clicks (
  `session_id` STRING,
  `event_time` TIMESTAMP(3),
  `event_type` STRING,
  `event_data` MAP<STRING, STRING>
) WITH (
  'connector.type' = 'kafka',
  'connector.version' = 'universal',
  'connector.topic' = 'clicks',
  'connector.properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format.type' = 'json',
  'format.fail-on-missing-field' = 'true',
  'update-mode' = 'append'
);

CREATE TABLE clicks_enriched (
  `session_id` STRING,
  `event_time` TIMESTAMP(3),
  `event_type` STRING,
  `event_data` MAP<STRING, STRING>,
  `derived_field1` STRING,
  `derived_field2` STRING
) WITH (
  'connector.type' = 'kafka',
  'connector.version' = 'universal',
  'connector.topic' = 'clicks-enriched',
  'connector.properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format.type' = 'json',
  'format.fail-on-missing-field' = 'true',
  'update-mode' = 'append'
);
```

Justification:

*   We create two Kafka topics (`clicks` and `clicks-enriched`) with 8 partitions each to handle the input rate of 20,000 events/s. This allows for a maximum produce traffic of 40 MB/s (8 partitions \* 5 MB/s per partition), which is above the required 10 MB/s (20,000 events/s \* 512 bytes per event / 1024).
*   We set the replication factor to 3 to ensure that both topics can survive the loss of any single Kafka broker without losing acknowledged data.
*   We configure the Flink job to use 8 task slots (one per Kafka partition) and set the parallelism to 8 to match the number of partitions.
*   We set the checkpointing interval to 10 seconds to achieve an end-to-end latency of below 1 second at p99.
*   We use the `filesystem` state backend with S3 as the checkpoint storage to ensure that checkpoints are persisted even in case of a failure.
*   We configure the Flink job to use at-least-once delivery guarantee by setting `execution.checkpointing.externalized-checkpoint-retention` to `RETAIN_ON_CANCELLATION`.
*   We set the restart strategy to `fixed-delay` with 3 attempts and a delay of 10 seconds to handle failures.
*   We create two Flink SQL tables (`clicks` and `clicks_enriched`) to read from and write to the corresponding Kafka topics. We use the `json` format and set `format.fail-on-missing-field` to `true` to filter out malformed events.
