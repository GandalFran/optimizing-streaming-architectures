### Justification of Main Values:
1. **Kafka Topic Configurations:**
   - **Partitions and Replicas:** Set to 10 partitions and 3 replicas to ensure high throughput and reliability. Given the input rate and event size, 10 partitions should be sufficient to handle the load.
   - **Retention and Segment Bytes:** Configured to retain data for 1 day with a segment size of 10 MB to balance storage and performance.

2. **Flink Configuration:**
   - **Parallelism:** Set to 10 to match the number of partitions in Kafka topics, ensuring load balancing.
   - **Checkpointing:** Configured for exactly-once processing with a 5-second interval to ensure data consistency.
   - **Memory and CPU:** Limited to 4 CPUs and 8 GiB to ensure efficient resource usage.
   - **State Backend:** RocksDB is used for state persistence with specific configurations to optimize performance.

3. **Kafka Connectors:**
   - **Partitioning:** Using 'round-robin' partitioner ensures balanced load across partitions.
   - **Format:** JSON format is used to match the input and output formats of the events.
