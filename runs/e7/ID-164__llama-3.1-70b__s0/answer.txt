```sql
-- Flink SQL CREATE TABLE statements for Kafka source and sink tables
CREATE TABLE clicks (
  `session_id` STRING,
  `event_time` TIMESTAMP(3),
  `event_type` STRING,
  `event_data` MAP<STRING, STRING>
) WITH (
  'connector.type' = 'kafka',
  'connector.version' = 'universal',
  'connector.topic' = 'clicks',
  'connector.properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format.type' = 'json',
  'format.derive-schema' = 'true',
  'update-mode' = 'append'
);

CREATE TABLE clicks_enriched (
  `session_id` STRING,
  `event_time` TIMESTAMP(3),
  `event_type` STRING,
  `event_data` MAP<STRING, STRING>,
  `derived_field1` STRING,
  `derived_field2` STRING
) WITH (
  'connector.type' = 'kafka',
  'connector.version' = 'universal',
  'connector.topic' = 'clicks-enriched',
  'connector.properties.bootstrap.servers' = 'my-cluster-kafka-bootstrap:9092',
  'format.type' = 'json',
  'format.derive-schema' = 'true',
  'update-mode' = 'append'
);
```

Justification:

*   We create two Kafka topics (`clicks` and `clicks-enriched`) with 10 partitions each to handle the input rate of 50,000 events/s. This allows for a maximum produce traffic of 50 MB/s (10 partitions \* 5 MB/s per partition), which is above the required 25.6 MB/s (50,000 events/s \* 512 bytes per event).
*   We set the replication factor to 3 for both topics to ensure that data is not lost in case of a single broker failure.
*   We configure the Flink job to use 10 TaskManagers with 4 CPU and 8 GiB of memory each. This allows for a maximum of 200,000 events/s (10 TaskManagers \* 20,000 events/s per TaskManager), which is above the required 50,000 events/s.
*   We set the checkpoint interval to 10 seconds and the checkpoint timeout to 10 seconds to achieve an end-to-end latency of below 1 second at p99.
*   We use the `filesystem` state backend with S3 as the checkpoint and savepoint storage to ensure exactly-once end-to-end delivery guarantee.
*   We configure the Flink SQL tables to use the Kafka connector with the `universal` version and JSON format. We derive the schema from the JSON data and use the `append` update mode.
